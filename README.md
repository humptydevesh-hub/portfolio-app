# Portfolio App — cloud deployment

This application can run without your laptop. Render hosts the FastAPI application, Render Postgres stores account and portfolio records, Cloudinary stores uploaded assets, and Resend sends account-verification emails.

## What the deployment file creates

The `render.yaml` Blueprint defines:
- A Render Python web service (Free plan).
- A managed Render Postgres database (paid `0.1c-256mb` compute plan).
- Generated `SECRET_KEY` configuration.
- Prompts for Cloudinary and Resend credentials.

The web service's Free plan may spin down after 15 minutes of inactivity and can take about a minute to wake up. The laptop is not involved, but this is not an always-on service. The Postgres database is a paid persistent database; do not replace it with Render's Free Postgres database for long-term data because that plan expires after 30 days.

## Deploy

1. Push or merge this branch to the GitHub repository.
2. In Render, choose **New → Blueprint**, connect `humptydevesh-hub/portfolio-app`, and select this branch (or the branch containing `render.yaml`).
3. Review the resources and costs before approving creation. The database plan is billable; the web service is Free and has cold starts.
4. Create a Cloudinary account and copy its cloud name, API key, and API secret into the prompted environment variables.
5. Create a Resend account, verify a sender/domain, and set `RESEND_API_KEY` and `EMAIL_FROM` (for example, a verified sender address).
6. Wait for the service health check to pass, then open the Render service URL. The frontend and API are served from the same origin.

## Local development

Install dependencies and run:

```bash
pip install -r requirements.txt
uvicorn main:app --reload
```

Without cloud credentials, local development uses SQLite, saves uploads to `static/uploads`, and prints OTP codes to the local terminal. Production refuses to fall back to ephemeral local uploads or terminal OTPs.

## Important data migration note

The current repository contains no SQLite database file, so this change cannot migrate existing local accounts, records, or uploaded files. If you have data on your computer, export/import it into the new Postgres database and upload the old files to Cloudinary before switching users to the cloud version. The app creates missing tables on first startup, but that is not a substitute for importing existing rows.

## Environment variables

| Variable | Purpose |
|---|---|
| `APP_ENV` | Set to `production` on Render |
| `DATABASE_URL` | Managed PostgreSQL connection string |
| `SECRET_KEY` | Stable JWT signing key; generated by the Blueprint |
| `CLOUDINARY_CLOUD_NAME` | Cloudinary account name |
| `CLOUDINARY_API_KEY` | Cloudinary API key |
| `CLOUDINARY_API_SECRET` | Cloudinary API secret |
| `RESEND_API_KEY` | Resend email API key |
| `EMAIL_FROM` | Verified sender address |
| `CORS_ORIGINS` | Optional comma-separated origins only if the frontend is hosted separately |

Never commit real credentials to Git.
